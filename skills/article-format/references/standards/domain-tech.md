### Keep a Changelog 变更日志规范

### Semantic Versioning 2.0.0 语义化版本

- 编号：`s5-023`　置信度：高
- 适用：软件版本号管理、依赖声明、发布流程
- 规格：版本号格式 MAJOR.MINOR.PATCH。不兼容的 API 变更升 MAJOR；向下兼容的新增功能升 MINOR；向下兼容的缺陷修复升 PATCH。预发布在补丁号后加连字符标识（如 1.0.0-alpha.1），构建元数据加号后标注。0.y.z 表示初始开发阶段，公开 API 不得视为稳定。数字不得有前导零。

### 缺陷报告规范（工程实践版）

- 适用：缺陷单、工单、问题反馈
- 规格：标题一行写清现象与位置，不用「有问题」类空话。正文必备：环境与版本、前置条件、复现步骤（编号、可逐步执行）、期望结果、实际结果、复现率、证据（日志、截图、录屏、请求响应）、影响范围与严重度、关联需求或改动。不可复现时须写明尝试过的条件。

### 代码评审规范

- 编号：`s5-032`　置信度：中
- 适用：Pull Request 模板、评审检查清单
- 规格：单次评审建议不超过 400 行改动，超过则拆分。评审者按四层检查：正确性（边界、错误路径、并发）、可维护性（命名、职责、重复）、契约（接口与数据格式兼容）、风险（安全、性能、数据迁移）。评论须分级标注（阻断/建议/提问），阻断项清零方可合并。作者须先自评并写清改动意图与验证方式。

### 运维手册 Runbook 规范

## 技术文档国际标准（12 条）

### IEC/IEEE 82079-1:2019 产品使用信息（使用说明）的编制 第1部分：原则和一般要求

- 编号：`s5-001`　置信度：高
- 适用：产品使用说明书、安装与操作手册、维护手册、在线帮助、软件用户指南
- 关联 profile：`tech-doc`
- 规格：将使用信息分为概念信息（产品与部件说明、控制与显示）、指导信息（按任务分步操作）、参考信息（故障排除、维护、技术数据）三类。要求识别并分层目标受众，安全信息置于每个相关操作步骤之前并配警示符号，结构按功能分区并建立检索索引；规定编制过程含策划、起草、验证、评价与更新，并给出可用性测试方法。

### ISO/IEC/IEEE 26514:2022 系统和软件工程 用户信息的设计与开发

- 编号：`s5-002`　置信度：高
- 适用：软件用户文档、帮助系统、开发者指南、信息产品规格书
- 关联 profile：`tech-doc`
- 规格：覆盖用户信息产品的全开发过程：确定用户需要什么信息、决定呈现方式、编制并交付。成品要求含任务导向内容与概念说明、封面与元数据、目录与导航、术语表、索引。对印刷与屏幕两种媒介分别规定版式、排版与可访问性要求，并要求建立设计策略与持续维护机制。

### ISO/IEC/IEEE 26511:2018 系统和软件工程 面向系统、软件与服务用户信息的管理者要求

- 编号：`s5-003`　置信度：高
- 适用：文档团队管理制度、文档项目计划、内容策略文件
- 规格：从管理者视角规定信息开发过程的策略、策划、执行与控制：内容策略与组合规划、文档计划与文档管理计划、资源与角色配置、进度与预算控制、质量度量与用户满意度监测、内容管理与复用、生命周期内的维护与归档。产出物为文档计划与文档管理计划两类关键文件。

### ISO/IEC/IEEE 26512:2026 系统和软件工程 用户信息产品与服务的采购方与供应方要求

- 编号：`s5-004`　置信度：高
- 适用：文档外包合同、招标与投标文件、供应商交付验收文件
- 规格：规定采购与供应双向的文档过程与信息项：采购计划、信息产品规格、工作说明书 SOW、招标书 RFP、投标书。要求把用户信息需求写进合同条款，明确交付物、验收标准、变更控制与知识产权归属；含文档管理计划与文档计划在采购流程中的使用方式。

### ISO/IEC/IEEE 26513:2017 系统和软件工程 用户信息的测试者与评审者要求

- 编号：`s5-005`　置信度：高

- 规格：规定用户信息的评审与测试过程：评审类型（技术评审、编辑评审、管理评审）、可用性测试设计与实施、测试环境与代表性用户选取、缺陷记录与跟踪、度量指标（任务完成率、任务时间、错误率、满意度）、结果判定与返修闭环。适用于印刷与屏幕文档，含硬件系统的配套文档。
